09AIAI · 开源模型
AI · 开源模型

阿里开源 Qwen 3.8 27B：基准全面超前代，但默认推理强度导致严重"过度思考"

阿里 Qwen 实验室发布 Apache 2.0 许可的 27B 视觉语言模型 Qwen 3.8 27B，官方基准全面超越前代 Qwen 3.6 27B 和自家闭源旗舰 Qwen 3.7-Plus。但评测发现其默认推理强度开在最高档，同一任务从 137 秒暴涨到 21 分钟。

模型支持图像与视频理解，原生上下文 262,144 token、可扩展至 1M，内置多 token 预测（MTP）加速。量化后约 17GB，一台高端笔记本即可运行。官方基准中，Terminal Bench 2.1 得 73.0（前代 63.4、闭源 Qwen 3.7-Plus 64.0），SWE-bench Pro 61.7，LiveCodeBench v6 90.3，视觉侧 OSWorld-Verified 84.3 为同表最高。

评测者 Simon Willison 发现官方默认 reasoning_effort 为最高档 xhigh，导致"极其夸张的过度思考"：提示"画一个鹈鹕骑自行车的 SVG"，默认设置下耗时 21 分钟、消耗 22,276 个推理 token 才产出 3223 个输出 token；关闭推理后同一提示只需 137 秒。他建议部署时"先忽略这个默认值，用 low 甚至关闭推理"。

对开发者意味着：17GB 的 27B 稠密模型把长上下文、多模态与工具调用全部装进本地，本地 coding agent 成为现实；但消费级硬件上默认 xhigh 是"糟糕的起点"，需主动调低推理强度。llama.cpp 已支持 MTP 投机解码，实测提速约 72%。

10工程工程 · AI 基础设施
工程 · AI 基础设施

MCP 协议走向无状态：开发者追问"这不就又变回 API 了吗？"

MCP 规范 7 月底版本取消协议会话机制，握手、会话标头从核心请求路径中移除，每个请求自带版本和身份；新增 Mcp-Method、Mcp-Name 两个必需标头，让网关无需解析 JSON-RPC 正文即可路由、限流和计量。

新规范意味着每个请求可落到任意实例，自动扩缩不再需要保留状态，负载均衡、渐进式发布等既有 API 基础设施可以直接复用。授权同步收紧：动态客户端注册已弃用、计划 2027 年夏季后移除，并采用 RFC 9207 做颁发者标识，客户端将规范服务器 URI 作为 RFC 8707 resource 发送。

开发者评论颇为犀利："我们发明了一种有状态协议，发现状态难以扩展，于是剥离了状态，最终得到的结果是'发一个 POST 请求就行'。REST 阵营已经得意地等待这一刻 20 年了。"辩护方则认为，MCP 真正的价值在于它是 AI 提供商认可的标准，"正因为如此，人们有强烈的动力真正去实现它"。

生态侧：Anthropic 报告其 MCP SDK 月下载量超过 4 亿次、今年增长三倍；但一次审计显示某客户服务器三个月仅 61 次工具调用、其中 58 次来自客户自己的工程师——"资金正在流向网关、注册中心和身份验证层，而不是服务器本身"。无状态化加标头路由，正是对暴露面与安全控制的直接回应。
