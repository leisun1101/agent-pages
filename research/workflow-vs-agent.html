定义

两种执行范式

在对比优劣之前，先明确定义。Anthropic 2024 年 12 月发布的 "Building Effective Agents" 是业界公认的分类基准。

Workflow + Graph Engineering

LLM 和工具通过预定义代码路径编排。图结构显式声明、可编译、可分析、可审计。

GitHub Actions · COVENANT · VADAOrchestra
"Workflows are systems where LLMs and tools are orchestrated through predefined code paths."
— Anthropic [13]

Loop Agent (Codex 范式)

LLM 在 while(tool_call) 循环中动态决定下一步。每次执行路径可能不同，不可预测。

OpenAI Codex · Claude Code · Devin · Cursor Agent
"Agents are systems where LLMs dynamically direct their own processes and tool usage."
— Anthropic [13]

AgentDebugX 原文："LLM agent failures are difficult to debug because the step where an error surfaces is often not the one that caused it."——错误显现的步骤往往不是导致错误的步骤。

LangGraph Durable Execution——图结构的独有能力

LangGraph [21] · Diagrid Catalyst 2.0 [22]
能力 Workflow DAG (LangGraph) Agent Loop (Codex)
节点级 checkpoint ✅ 每个节点存快照 ❌ 只有 conversation
Time Travel ✅ fork 任意历史点 ❌ 无法回到中间步骤
Human-in-the-loop ✅ interrupt() 暂停 ❌ 需额外编码
Fault Recovery ✅ 从上个成功节点恢复 ❌ 全有或全无

为什么 Agent Loop 做不到：Agent loop 的每一步都依赖前一步的全部上下文（conversation history），没有结构化的"状态快照"。你不能"回到第 3 步，修改输入，看不同结果"——因为 loop 没有暴露中间步骤。2026 年 7 月 Diagrid Catalyst 2.0 的发布验证了 durable execution 已成为生产级 agent 系统的刚需 [22]。

维度六

速度：每一步都在等模型"想"

Agent Loop 的每一步都需要完整的 LLM 推理往返（prompt → 模型推理 → 工具调用 → 模型再推理）。Workflow DAG 的确定性节点（HTTP / Chat / Custom）不需要 Agent 推理——它们直接执行，延迟可降低一个数量级。

Chat（小模型结构化输出） ~1–2s ⚠️ 轻量 LLM

Agent Loop（每步都推理） ~3–5s × N 步 ✅ 每步都推理

核心洞察：Agent Loop 的延迟是乘法增长的——每多一步就多一个完整的 LLM 推理往返（prompt 处理 + 模型推理 + 工具执行 + 模型再推理）。Workflow DAG 的延迟是加法的——只有真正需要推理的 Agent 节点才调用 LLM，其余节点直接执行。一个 10 步任务里如果只有 1 步真正需要 Agent 推理，Workflow 的延迟大约是 Agent Loop 的 1/4。

延迟复合效应：Agent Loop 不仅每步慢，而且不能并行——因为下一步依赖上一步的输出（模型要看到完整 conversation history 才能决策）。Workflow DAG 可以让不互相依赖的节点并行执行，进一步压缩总延迟。

维度七

多模型优化：每个节点用最合适的模型

声明式 YAML schema 让每个节点独立配置模型——简单分类用便宜的小模型，复杂推理才用贵的大模型。Agent Loop（Codex/Claude Code）锁死单一模型，不管任务简单还是复杂，每一步都烧同一个模型。

统一理论

Progressive Crystallization

2026 年 7 月的最重要发现：Agent 不是终态，而是发现机制。验证过的 Agent 行为会"结晶"为确定性 Workflow。这不是对立，而是生命周期。

实践指南

什么时候用什么

不回避反方论点——Agent Loop 在特定场景仍然更好。

✅ 选 Workflow DAG

  • 任务可分解为固定步骤
  • 高频执行（成本可预估至关重要）
  • 合规/审计需求（金融、医疗、法律）
  • 需要可复现性
  • 团队 AI 经验有限
  • 企业生产环境

⚠️ 选 Agent Loop

  • 步骤数量未知（开放性探索）
  • 低频但高价值（错误成本 >> 计算成本）
  • 创造性/探索性任务
  • 一次性任务（定义 workflow 不值得）
  • 调试从未见过的 bug
  • 快速原型

"找到最简单的可行方案，只在需要时才增加复杂度。这可能意味着根本不构建 agentic 系统。"

— Anthropic, "Building Effective Agents" [13], 2024-12
